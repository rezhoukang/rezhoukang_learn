Request（请求） = 前端发给后端的东西（"我要登录，这是我的账号密码"）
Response（响应） = 后端返回给前端的东西（"登录成功，这是你的 token"）
POJO（普通 Java 对象，Plain Old Java Object） = 只有属性 + get/set 的单纯 Java 类，没业务没注解，其他 PO/DO/DTO/VO 都是它变出来的
PO（持久化对象，Persistent Object） = 和数据库表一一对应的类，字段跟表完全对齐，直接交给 ORM 存库
DO（数据对象，Data Object） = 和 PO 基本一回事，阿里规约推荐叫 DO，代表数据库映射实体
DAO（数据访问对象，Data Access Object） = 不是实体类是接口/类，负责数据库增删改查（Mapper、Repository 都算它）
BO（业务对象，Business Object） = 把多个 DO/PO 拼起来装业务数据的对象，在 Service 内部用
DTO（数据传输对象，Data Transfer Object） = 跨层传数据的盒子，Service→Controller，接收前端参数 / 返回给前端
VO（视图对象，View Object） = 专门给前端页面展示的对象，过滤掉密码等敏感字段
DTO：双向
接收前端提交的数据（入参 DTO）；也可以返回数据。
例：UserCreateDTO 接收新增用户表单。
VO：单向，只往外输出
只给前端页面看，不会拿来接收请求参数。
例：UserVO 用户详情页展示数据。
