# 线程与协程

## 本质区别

| | 线程（内核线程） | 协程（用户线程） |
|--|---------------|----------------|
| **谁调度** | 操作系统内核 | 程序自己（用户态） |
| **切换成本** | 高（需进入内核态） | 低（用户态完成） |
| **内存占用** | 大（MB 级） | 小（KB 级） |
| **最大数量** | 几千到上万 | 几十万甚至更多 |
| **并行能力** | 真正并行 | 本质是并发，底层复用线程 |

## 线程池

线程创建销毁成本高，**线程池**就是提前养一批线程，有任务直接丢进去跑，用完不销毁，循环利用。

**核心参数：** 核心线程数、最大线程数、任务队列、拒绝策略

**流程：** 任务进来 → 核心线程没满直接跑 → 满了丢队列排队 → 队列也满了开临时线程 → 还满就拒绝

**适用：** 大量短任务（如 Web 请求）、限制并发防资源打满

## 为什么用协程

传统线程太"贵"——一个线程有线程栈、内核对象，开 1 万个就可能爆内存，且切换需进入内核态，CPU 开销大。

协程的核心目标：**用更低的成本支持更高的并发**。一个协程只需几 KB 内存（如 Go 的 Goroutine 初始栈才几 KB），轻松开几十万。

## 运行原理

协程 ≠ 并行。核心是**主动让出执行权**：

- 协程遇到网络 IO（如等待数据库、RPC、HTTP 响应），不会像线程那样阻塞，而是主动告诉调度器："我要等数据，你先去执行别人"
- 数据回来了再切回来继续执行

所以协程**特别适合 IO 密集型场景**（Web 服务、数据库请求、RPC 调用、网络爬虫等），大量时间其实都在等 IO。

## 协程与线程的关系

协程底层还是运行在线程上的，**多个协程复用少量线程**。

以 Go 的 GMP 模型为例：几十万个 Goroutine 最终只跑在几个系统线程上。
- **线程**负责真正执行 CPU
- **协程**负责提高并发调度效率

## 缺点

1. **不适合 CPU 密集**——CPU 计算不会主动让出执行权
2. **阻塞操作会拖死调度**——同步 IO、sleep、阻塞锁如果底层没做异步化处理，整个线程可能卡住
3. **调试难度高**——调用链变复杂

## 一句话总结

**传统线程**：操作系统调度，成本高，切换重，但真正并行。  
**协程**：用户态调度，成本低，切换快，特别适合高并发 IO 场景。  

相当于程序自己实现了一套更轻量的"线程系统"。

IO = Input/Output（输入输出）。

在计算机里，指的是数据读写操作，比如：

读数据库（从硬盘/网络拿数据）
发 HTTP 请求（等待远程服务器返回）
读写文件（硬盘读写）
这些操作的特点是CPU 基本不干活，主要都在等——等硬盘转完、等网络数据包回来。所以叫 IO 等待。
