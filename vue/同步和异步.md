# 同步 vs 异步

**同步**：一行一行执行，上一行搞完才到下一行。

```ts
console.log('1')
console.log('2')
console.log('3')
// 输出：1 → 2 → 3
```

**异步（回调）**：不等结果，先往下跑，结果回来再处理。

```ts
console.log('1')
setTimeout(() => console.log('2'), 1000)  // setTimeout 是 JS 内置 API，等 1 秒
console.log('3')
// 输出：1 → 3 → 2
```

**async/await**：用同步的写法处理异步逻辑，内部等待但外部不阻塞。

```ts
async function load() {
  console.log('1')
  await new Promise(r => setTimeout(r, 1000))  // Promise 是 JS 内置 API，装着一个未来的结果；setTimeout 也是内置 API
  console.log('2')
}
load()
console.log('3')  // 外部不受影响
// 输出：1 → 3 →（1秒后）→ 2
```

## 返回 Promise 是什么意思

```ts
async function demo() {
  // setTimeout 支持多传参数，第三个会传给 resolve
  const box = new Promise(resolve => setTimeout(resolve, 1000, '时间到'))
  console.log(box)          // Promise {<pending>}  ← 不是 '时间到'，是个包装盒
  const result = await box
  console.log(result)       // '时间到'  ← await 等 1 秒，拆盒取出里面的值
}
demo()  // 调用函数，不写这行代码不执行
```

控制台输出：

```
Promise {<pending>}
时间到
```

（第一条立即打印，第二条等 1 秒后打印）

**返回 Promise = 返回一个包装盒，里面的东西还没到。需要用 `await` 等东西到了，再拆开取出来。**

## 异常处理

异步操作可能失败（网络断开、超时），必须用 `try/catch` 包起来：

```ts
async function load() {
  try {
    const res = await axios.get('/api/user')   // axios 是 HTTP 库；get 发 GET 请求，返回 Promise
    console.log(res.data)                      // 成功
  } catch {
    alert('加载失败')                           // alert 是浏览器内置 API，弹提示框
  }
}
```

## 总结

```
同步：写法→同步  结果→同步  阻塞→阻塞（页面卡死）
回调：写法→同步  结果→异步  阻塞→不阻塞（看不懂顺序）
async/await：写法→同步  结果→同步  阻塞→不阻塞（最优）
```

`async/await` 实现了"同步的写法 + 同步的结果 + 异步的性能"
