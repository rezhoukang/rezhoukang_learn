# Redis

**Redis** = 内存数据库，数据在内存里，读写极快。常用于缓存、并发锁、计数器等。

## 主要用途

| 用途 | 说明 |
|------|------|
| **缓存** | 热点数据放 Redis，减轻 MySQL 压力 |
| **分布式锁** | 多线程/多服务争抢资源时保证只有一个能拿到 |
| **计数器** | 点赞数、访问量（`INCR` 原子自增） |
| **会话存储** | 登录态存 Redis，多服务器共享 |
| **消息队列** | 列表结构做简单的生产者/消费者 |
| **排行榜** | 有序集合 `ZADD` 按分数排序 |

## 原子性 vs 锁

**单条命令有原子性**（`INCR`、`DECR`），但多条命令组合起来就没有原子性了。

### 单条命令：天然原子性

```redis
INCR article:1001:views   -- 自增1，Redis 内部保证并发安全
```

多个用户同时 `INCR`，不会错乱。一条命令搞定，不需要锁。

### 多条命令：原子性不够，需要锁

比如"检查库存 → 扣减"两步：

```redis
-- 没有锁的情况（并发问题）：
GET stock:1001             -- 用户A读到1
GET stock:1001             -- 用户B也读到1
DECR stock:1001            -- 用户A减到0
DECR stock:1001            -- 用户B减到-1（超卖！）
```

两步操作之间可能有其他请求插进来，单条原子性救不了。这时需要锁：

```redis
-- 加锁：SET NX（键不存在才成功）
SET lock:stock NX EX 10    -- 用户A抢到锁
GET stock:1001             -- 读到1
DECR stock:1001            -- 减到0
DEL lock:stock             -- 释放锁

-- 用户B再来：
SET lock:stock NX EX 10    -- 失败，锁还在 → 等待或放弃
```

### 乐观锁 vs 悲观锁

Redis 没有像 MySQL 那么完善的行锁机制，但可以用两种思路：

| | 乐观锁（WATCH） | 悲观锁（SET NX） |
|--|---------------|----------------|
| 做法 | `WATCH key` → 读数据 → `MULTI` 提交 → 别人改了则提交失败，重试 | `SET NX` 抢锁 → 执行业务 → `DEL` 释放 |
| 冲突多时 | 一直重试，性能差 | 直接拒掉，性能好 |
| 适用 | 冲突少的场景 | 冲突多的场景（秒杀） |

```redis
-- 乐观锁：WATCH + MULTI
WATCH stock:1001          -- 监视这个键
GET stock:1001            -- 读到1
MULTI                     -- 开启事务
DECR stock:1001           -- 减到0
EXEC                      -- 提交，如果 stock:1001 被改过就失败
```

```redis
-- 悲观锁：SET NX 互斥
SET lock:stock NX EX 10   -- 抢不到就放弃，简单粗暴
DECR stock:1001
DEL lock:stock
```

**一句话：原子性管单条命令，锁管多条命令组合。** 乐观锁适合冲突少（WATCH 重试），悲观锁适合冲突多（SET NX 互斥）。

## 事务与锁的区别

| | MySQL 事务 | Redis 事务/锁 |
|--|-----------|-------------|
| 目的 | 保证多个 SQL 同时成功或同时失败 | 保证同一时间只有一个操作能执行 |
| 机制 | `BEGIN` → SQL → `COMMIT` / `ROLLBACK` | `SET NX` 互斥锁 / `INCR` 原子操作 |
| 使用场景 | 转账（A 扣钱、B 加钱必须同时成功） | 秒杀（一万个人抢一个名额，只放一个人进） |
| 性能影响 | 较大（行锁、死锁检测） | 极小（内存操作） |

## Redis + MySQL 配合

```
查数据 → 先查 Redis（缓存）
        ├── 有 → 直接返回（快）
        └── 没有 → 查 MySQL → 写回 Redis → 返回
```

```
写数据 → 先写 MySQL（保证数据不丢）
        → 删 Redis 缓存（下次查时自动刷新）
```
